# Guardrails: things never done without asking

These rules protect the live channel and the work. Each one exists because of
something that really happened or nearly did.

## The live YouTube channel

- **A live video is deleted, replaced or hidden only when the owner names that
  exact video.** Never on a guess that "this one is probably bad".
- **Before deleting or replacing, the video's id and title are stated.**
- **Deleting is permanent.** It can't be undone.
- **Replacing is not a swap.** It deletes the old video and uploads a new one.
  The new one gets a new link, and the old views, likes and comments are lost.
- **Publish times of scheduled reels are changed only when the owner asks**,
  and the old and new times are shown first.
- **Never two reels in one slot**, and nothing published immediately unless
  the owner asks.
- **No large batch of uploads** unless the owner asked for those reels.
- **Instagram is never automated.** The owner posts there by hand.

## Login details

- The YouTube login files are never shown, shared or published.
- If a login detail is ever exposed, it is reset straight away, even if it
  seems nobody saw it.

## Deleting files

- Files are never deleted in bulk with wildcards. Each file is named.
- The full list of files is shown **before** anything is deleted.
- Downloaded talks and finished reels are kept unless the owner says
  otherwise.
- If something looks missing, check before assuming it's lost. Once, "missing"
  files had simply been removed by the owner.

## The rules themselves

- A rule in `STYLE.md` changes only with the owner's agreement.
- A Sanskrit or Madhwa name is never spelled from a guess. If it isn't in the
  confirmed list, it is flagged.
- A one-off instruction is not turned into a standing rule without asking.

## Staying in scope

- A reel that isn't part of the current task is not rebuilt or re-uploaded,
  even if it could be improved. It is suggested instead.
- Uploading a new reel that passed every check is part of making it and needs
  no extra approval. Deleting, replacing or hiding still does.

## Adding a guardrail

When something nearly goes wrong, a rule is added here and the story goes in
`CHANGELOG.md`, so the rule never looks arbitrary later.
